# 什么是 AI Coding

## 定义
**AI Coding**（AI 辅助编程）是指利用大语言模型（LLM）参与软件开发的全流程，涵盖从需求理解、代码生成、调试修复、测试编写到文档维护的各个环节。

它不是"AI 写代码"这么简单，而是一套**人机协作的新型工作流**：

```
开发者 ──意图/约束──> AI 模型 ──代码/方案──> 开发者 ──审查/调整──> 代码库
       ↑                                                    │
       └──────────────反馈/迭代──────────────────────────────┘
```

## 与传统开发的差异
| 维度 | 传统开发 | AI Coding |
| --- | --- | --- |
| **代码产出主体**| 人类开发者 | AI 生成 + 人类审查 |
| **知识载体**| 开发者脑中 + 文档 | Prompt + 上下文 + agents.md |
| **学习路径**| 文档、Stack Overflow | 对话式 + Prompt 工程 |
| **瓶颈环节**| 写代码速度 | Prompt 质量与上下文管理 |
| **协作模式**| 写 → 提 PR → Review | 描述意图 → AI 生成 → Review |
| **失败模式**| Bug | "看起来对但跑不起来"的代码 |

## AI Coding 能做什么
- **生成新代码**：组件、Hook、工具函数、API 客户端
- **重构现有代码**：变量改名、抽象提取、API 升级适配
- **修复 Bug**：根据错误信息定位与修复
- **写测试**：单元测试、组件测试、E2E 测试
- **生成文档**：JSDoc、README、API 文档
- **代码审查**：自动发现代码问题与改进建议
- **翻译与迁移**：从一种框架/语言迁移到另一种

## AI Coding 不能做什么
- **架构决策**：AI 缺乏对业务、团队、组织上下文的深度理解
- **产品取舍**：AI 不懂用户、市场、商业模型
- **安全合规判定**：最终责任必须在人
- **跨团队协调**：沟通、推进、谈判仍然需要人
- **创造性突破**：颠覆性创新仍依赖人

::: tip 核心认知
AI Coding 的本质是**把开发者从"打字员"升级为"决策者"**。开发者的工作重心从"写代码"转向"描述意图、审查结果、迭代优化"。
:::

## 前端领域的特殊性
前端开发有几个独特属性，让 AI Coding 在这里**收益特别明显**：

1. **样板代码多**：组件、路由、状态管理的模板代码占大头
2. **视觉反馈直观**：UI 即时可见，方便 AI 自我验证
3. **生态成熟规范**：React/Vue/TS 等都有强约定，AI 容易学习
4. **迭代频繁**：小改动多，AI 生成小改动的速度优势巨大

但也面临独特挑战：
- 设计还原度（设计稿 → 代码）
- 跨浏览器兼容
- 多端适配（Web / 小程序 / 移动端）
- 性能优化（涉及运行时行为）
