类型注解的 4 个常见误区：
  1. ❌ 「加了注解就安全」 → 注解不影响运行时，x: int = "hello" 不会报错（只是 mypy/pyright 静态检查会告警）
  2. ❌ 「所有变量都要写注解」 → 局部临时变量不必，函数签名 / 公开 API 必须
  3. ❌ 「list 没用，要写 List」 → 3.9+ 用内置 list[int] 即可，更快、更短
  4. ❌ 「写了类型就不需要测试」 → 类型只检查类型，不检查逻辑正确性，两者互补

🔒 3. Python 特殊命名约定（_ / __ / __xxx__）

Python 的"私有"分三档：_ 约定、__ 名称改写、__xxx__ 魔术方法。

写法含义JS / TS 对照
name 公有（默认） this.name
_name 约定私有（提示"别从外部碰"，但实际可访问） TS private name（编译时）/ JS _name（约定）
__name 名称改写（真私有）：实际存为 _ClassName__name，子类不能直接覆盖 JS #name（真私有字段）
__name__ 魔术方法（系统调用，如 __init__、__str__） JS Symbol.xxx（如 Symbol.iterator）
__name___ ❌ 末尾单下划线（避免跟关键字冲突：class_） ❌ 无

🔄 列表推导式（List Comprehension）

把「遍历 + 筛选 + 映射」三件事写到一行里，可读性比 map/filter 链还高。语法：[表达式 for 变量 in 可迭代对象 if 条件]。

  .filter(x => x > 2)
  .map(x => x * x);

for (const a of [1, 2, 3]) {
  for (const b of ["x", "y"]) {
    pairs.push([a, b]);
  }
}

⚡ 生成器表达式（Generator Expression）

把推导式的 [ ] 换成 ( )，结果不是列表而是「惰性迭代器」——不一次性占内存，按需产出值。大文件、大数据集首选。

JS：generator function

function* gen() {
  for (let i = 0; i < 10; i++) {
    yield i * i;
  }
}
const it = gen();
it.next();   // { value: 0, done: false }

Python：把 [ ] 变 ( )

gen = (x*x for x in range(10))
next(gen)    # 0
next(gen)    # 1

# 一次性消费（跟列表效果相同）
sum(x*x for x in range(10))   # 285
列表 vs 生成器：内存差几个数量级 
import sys

# 列表推导式：立即在内存里建好整个列表
big_list = [x*x for x in range(1_000_000)]
sys.getsizeof(big_list)        # ~8 MB（实际看实现，约 8.5 MB）

# 生成器表达式：只占一个对象大小，按需算
big_gen = (x*x for x in range(1_000_000))
sys.getsizeof(big_gen)         # ~200 字节！

# 都能被 for / sum / any / all 等迭代消费
sum(big_gen)                   # 正确算出总和
sum(big_list)                  # 一样
场景推荐原因
需要多次遍历 / 取长度 / 索引列表推导式 [ ]列表是具体容器，支持 len()、[i]、多次 for
只遍历一次 + 算聚合（sum/any/max）生成器表达式 ( )惰性求值，省内存
数据流式处理（大文件、日志）生成器表达式 ( )一行 (line for line in f) 就能逐行处理 GB 级文件
要塞进 set / dict / 排序列表推导式（再转换）set(...)、sorted(...) 都要可迭代对象
结果很小（< 1000 项）两者都行性能差异可忽略，选顺眼的
小坑：生成器是「一次性」的——消费完就空了，再 for 一次会拿到空值。需要复用就 list(gen) 转成列表，或者重新生成一次。

class Vector:
    """支持 print、len、[]、迭代、== 的二维向量"""

    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):             # REPL 显示
        return f"Vector({self.x}, {self.y})"

    def __str__(self):              # print() 显示
        return f"({self.x}, {self.y})"

    def __eq__(self, other):        # ==
        if not isinstance(other, Vector):
            return NotImplemented
        return self.x == other.x and self.y == other.y

    def __len__(self):              # len()
        return 2

    def __getitem__(self, i):       # v[0]
        if i == 0: return self.x
        if i == 1: return self.y
        raise IndexError

    def __iter__(self):             # for x in v
        yield self.x
        yield self.y

v = Vector(3, 4)
print(v)                # (3, 4)        ← __str__
repr(v)                 # Vector(3, 4)  ← __repr__
v == Vector(3, 4)      # True          ← __eq__
len(v)                  # 2             ← __len__
v[0]                    # 3             ← __getitem__
list(v)                 # [3, 4]        ← __iter__

从 JS 切到 Python，最容易栽跟头的 6 个点。每条都给出「错在哪 → 怎么改」。

1️⃣ 字符串不可变

JS（报错）

2️⃣ 列表是引用赋值

JS（结构共享）

b.push(4);
console.log(a);        // [1, 2, 3, 4]

Python（行为一致）

b = a.copy()           # 或 a[:] 或 list(a)

JS 默认值是新建的

  return lst;
}

add(2);  // [2]  ← 每次新数组

    return lst

# ✅ 正确写法
def add(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst

# ===== 被测代码（src/todo.py）=====
"""极简 TODO 工具：增删查 + 列表 + 持久化到 TODO_FILE"""
import json
import os
from pathlib import Path

TODO_FILE = os.environ.get("TODO_FILE", "todos.json")

def load_todos() -> list[dict]:
    p = Path(TODO_FILE)
    if not p.exists():
        return []
    return json.loads(p.read_text(encoding="utf-8"))

def save_todos(todos: list[dict]) -> None:
    Path(TODO_FILE).write_text(
        json.dumps(todos, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )

def add_todo(text: str) -> dict:
    """新增一条 TODO，返回创建的对象。text 不能为空。"""
    if not text or not text.strip():
        raise ValueError("TODO 内容不能为空")
    todo = {"id": len(load_todos()) + 1, "text": text.strip(), "done": False}
    save_todos(load_todos() + [todo])
    return todo

def list_todos(only_undone: bool = False) -> list[dict]:
    todos = load_todos()
    return [t for t in todos if not t["done"]] if only_undone else todos

def complete_todo(todo_id: int) -> bool:
    """标记完成，返回是否真的改了状态。"""
    todos = load_todos()
    changed = False
    for t in todos:
        if t["id"] == todo_id and not t["done"]:
            t["done"] = True
            changed = True
    save_todos(todos)
    return changed

def main() -> None:
    """命令行入口：依次打印所有未完成 TODO"""
    for t in list_todos(only_undone=True):
        print(f"[{t['id']}] {t['text']")

模板里 5 条要求的拆解：
  • ①「覆盖每个公共函数」→ test_xxx 按函数拆（看上面 8 条测试的命名）
  • ②「正常 / 异常 / 边界」→ pytest.raises + parametrize（空字符串、None、负数、不存在的 id）
  • ③「tmp_path 隔离数据文件」→ 每个测试拿一个独立临时目录，不污染真实数据、并行安全
  • ④「capsys 验证 print」→ capsys.readouterr().out 拿 stdout，专门测 main() 这类 CLI 入口
  • ⑤「monkeypatch 替换 TODO_FILE」→ 把模块里的常量 / 函数替换成临时值，不污染全局环境（monkeypatch.setattr(module, "TODO_FILE", ...)）
LLM 初稿的典型盲区：① 不会主动质疑需求（例：add_todo 的 id = len()+1 其实有 bug——如果中途删除 todo，id 会重复，但 LLM 默认「能跑就行」）② 不会覆盖「你没在模板里提到」的边界（并发、文件锁、编码异常）③ 参数化写得不全。下面 ②③④ 步就是补救。

③ hypothesis：自动 fuzz 边界用例

hypothesis 是 Python 的 property-based testing 库：你只描述「输入应该满足什么不变量」，它自动生成几百组「刁钻」输入。专治 LLM 想不全、人类想不全的边界（空字符串、超大整数、Unicode emoji、NaN、None 嵌套……）。

JS：fast-check

import fc from 'fast-check';

test('reverse twice = original', () => {
  fc.assert(
    fc.property(fc.array(fc.integer()), (arr) => {
      return JSON.stringify([...arr].reverse().reverse())
          === JSON.stringify(arr);
    })
  );
});

Python：hypothesis

from hypothesis import given, strategies as st

@given(st.lists(st.integers()))
def test_reverse_twice(xs):
    assert xs[::-1][::-1] == xs
给 pricing 函数加 hypothesis 测试（自动暴露负价 bug） 
import pytest
from hypothesis import given, strategies as st, assume
from src.pricing import apply_discount

# 1. 折扣不应该是负数（业务不变量）
@given(
    price=st.floats(min_value=0, max_value=1e6, allow_nan=False),
    code=st.sampled_from([None, "", "STUDENT", "BLACKFRIDAY", "UNKNOWN", "VIP"])
)
def test_discount_never_negative(price, code):
    """价格 ≥ 0 时，折扣后必须 ≥ 0"""
    assert apply_discount(price, code) >= 0

# 2. STUDENT 折扣 = 原价 × 0.5
@given(price=st.floats(min_value=0, max_value=1e6, allow_nan=False))
def test_student_is_half_price(price):
    assert apply_discount(price, "STUDENT") == pytest.approx(price * 0.5)

# 3. 任何 code 都不应让价格涨上去
@given(
    price=st.floats(min_value=0, max_value=1e6, allow_nan=False),
    code=st.text(min_size=0, max_size=20)
)
def test_no_markup(price, code):
    """任何优惠码都不应让价格变高"""
    assert apply_discount(price, code) <= price

# 4. 字符串 + 特殊字符不崩
@given(code=st.text(min_size=1, max_size=50))
def test_unicode_codes_dont_crash(code):
    """随便输入任何字符串都不应抛异常"""
    apply_discount(100.0, code)

# 上面 test_discount_never_negative 会在 price=负数时挂掉，
# 这就是「LLM 初稿没覆盖到的 bug」

uv 常见坑 & 解决：
  • uv: command not found → 装完后没重启终端，或 PATH 没加 ~/.local/bin（macOS/Linux）。装完脚本会提示，按它给的提示操作
  • error: No interpreter found → 系统里没 Python，uv python install 3.12 装一个，不用先装系统 Python
  • lock 文件和实际环境不一致 → 跑 uv lock --check（CI 用），不一致就 uv sync
  • 想离线装包 → uv pip install --offline xxx（要求之前下过，或 UV_OFFLINE=1）
  • uv.lock 要不要进 git？要进（前端 lockfile 同理），保证协作环境一致
  • 老项目用 pip + venv，迁移到 uv 会冲突吗？不会，uv 自动复用现有 .venv，也能并存
  • 想清缓存重装 → uv cache clean，缓存默认在 ~/.cache/uv
  • 想用 uv.lock 但不想每次同步太严？→ uv sync --frozen（只装不更新 lock）

挑选原则（10 条速记）：
  1. 先看 PyPI 下载量 + GitHub star 数（> 1k stars 才考虑）
  2. 看 最近一次 commit 时间（超过 1 年没更新的慎用）
  3. 看 issue 处理速度（核心 issue 长期无人回的慎用）
  4. 优先选 新项目用 🆕 标记的（uv / FastAPI / httpx / polars / ruff / pydantic v2）
  5. 同类型库只选 一个（避免互相转换开销）
  6. 能用 标准库 就不用第三方（datetime / json / pathlib / urllib）
  7. AI/LLM 项目 先确定模型来源 再选 SDK（OpenAI 兼容协议用 openai + base_url 即可）
  8. 数据库 先看并发模型：异步（asyncpg / motor / sqlalchemy async）vs 同步（psycopg / pymongo / sqlalchemy sync）
  9. 测试 只装必要的：pytest + pytest-cov + hypothesis 三件套够用
  10. 遇到 不知道选啥 → 看 awesome-python 或 awesome-python-data-science
