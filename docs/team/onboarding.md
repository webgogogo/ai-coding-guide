# 团队上手路径

## 为什么需要标准化上手
新成员加入团队时：

- **没有标准化**：每人摸索 1-2 周才上手
- **效率损失**：前几周产出很低
- **质量不稳**：早期容易出 Bug
- **体验差**：新人感到孤立

有标准化上手流程：

- **快速融入**：1 周内上手 AI Coding
- **规范一致**：从第一天就遵守团队规范
- **高效产出**：第 2 周就能贡献代码
- **体验好**：感到被支持

## 7 天上手路径

### Day 1：环境与工具
**目标**：搭建好开发环境

#### 上午
```bash

# 1. 安装基础工具
- Node.js (LTS)
- pnpm / npm / yarn
- Git
- VS Code 或 Cursor

# 2. 克隆项目
git clone <repo>
cd <project>
pnpm install

# 3. 启动项目
pnpm dev
```

#### 下午
```bash

# 4. 安装 AI 工具
- Cursor（推荐）
- 或 Trae Solo
- Claude Code（CLI）

# 5. 配置 AI 工具
- 打开项目根目录的 agents.md
- 在 Cursor 中确认加载
- 配置模型、API Key

# 6. 第一次 AI 对话
> 你好，请用 1 段话介绍这个项目做什么
> （验证 AI 理解了项目）
```

**Day 1 产出**：
- 开发环境就绪
- AI 工具配置完成
- 能用 AI 解释项目结构

### Day 2：阅读规范
**目标**：理解团队 AI Coding 规范

#### 必读文档
```markdown

## Day 2 阅读清单
- [ ] README.md（项目概述）
- [ ] agents.md（AI Coding 规范）
- [ ] CONTRIBUTING.md（贡献指南）
- [ ] ARCHITECTURE.md（架构文档）

## 重点关注
- 命名规范
- 目录结构
- Git 流程
- PR 流程
- 测试要求
```

#### 理解 agents.md
```bash

# 和 Lead 过一遍 agents.md

# 重点：
- 5 条最重要的规则是什么？
- 团队的命名约定？
- 禁止事项？
- 偏好？
```

**Day 2 产出**：
- 理解项目规范
- 能背诵 5 条最重要规则

### Day 3：第一个 AI Coding 任务
**目标**：完成第一个完整任务

#### 任务类型
```bash

# 推荐：从简单的开始
- 修复一个小的 UI 问题
- 添加一个新的小功能
- 写一个工具函数 + 测试
```

#### 完整流程
```bash

# 1. 创建分支
git checkout -b feature/your-first-task

# 2. 任务规划
> 我要做 X，请先告诉我方案

# 3. AI 生成代码
> 按方案实施

# 4. 跑测试
pnpm test

# 5. 自我 Review
> 请审查你写的代码

# 6. 提交
git add .
git commit -m "feat: ..."
git push

# 7. 创建 PR
```

**Day 3 产出**：
- 第一个 PR 合并
- 体验完整流程

### Day 4-5：实战多个任务
**目标**：熟练 AI Coding 工作流

#### 任务列表
```bash

# Day 4：
- 完成 2-3 个中等任务
- 体验 Plan Coding
- 写测试

# Day 5：
- 完成 1 个稍大的任务
- 体验 Spec Coding（如适用）
- 参与他人 PR 的 Review
```

#### 重点学习
```markdown

## 重点掌握
- 如何写好 Prompt
- 如何利用 @ 引用
- 如何让 AI 自审
- 如何处理 Review 反馈
```

**Day 4-5 产出**：
- 完成 3-5 个任务
- 开始熟悉代码库
- 掌握 AI Coding 工作流

### Day 6：参与团队协作
**目标**：融入团队协作流程

#### 活动
```bash

# 1. 参加周会
- 分享这周的学习
- 听其他人分享

# 2. Review 他人的 PR
- 学习团队代码风格
- 提出建设性反馈

# 3. 1-on-1 与 Lead
- 讨论遇到的问题
- 反馈流程改进建议
```

**Day 6 产出**：
- 参与团队 Review
- 建立协作关系

### Day 7：总结与展望
**目标**：回顾 + 规划

#### 自我评估
```markdown

## 第一周回顾

- [ ] AI 工具使用

- [ ] Git 流程
- [ ] PR 流程

### 还需加强
- [ ] 业务理解
- [ ] 复杂任务处理
- [ ] 测试技巧
- [ ] 性能优化

### 下周目标
- ...
```

**Day 7 产出**：
- 自我评估完成
- 下阶段目标明确

## 不同角色的上手

### 初级开发者
```markdown

## 重点
- 基础工具使用
- 简单任务完成
- 学习代码规范
- 多 Review 他人代码

- 急于承担复杂任务
- 追求完美

```

### 中级开发者
```markdown

## 重点
- 复杂任务独立完成
- 用 AI 处理重构
- 写测试
- 指导初级成员

## 不必
- 立刻承担关键模块
- 改变现有架构
```

### 高级开发者 / Lead
```markdown

## 重点
- 架构理解
- AI Coding 工具深度配置
- 规范制定参与
- 团队培训

## 不必
- 自己写所有代码
- 忽略规范（即使是新人）
```

## Buddy 制度

### 什么是 Buddy
新人配一个**老员工**作为 Buddy：

```
新人 ←→ Buddy（老员工）
        ↓
    1 对 1 指导
    日常问题解答
    代码 Review
    团队文化传递
```

### Buddy 的职责
```markdown

## Buddy 责任
- [ ] 第 1 周每天 1-on-1（30 分钟）
- [ ] 解答 AI Coding 工具问题
- [ ] 帮 Review 第一个 PR
- [ ] 介绍团队文化、规范
- [ ] 反馈新人遇到的问题
```

### 新人的责任
```markdown

## 新人责任
- [ ] 主动提问
- [ ] 按时完成任务
- [ ] 接受反馈
- [ ] 记录学习笔记
- [ ] 一周后反馈体验
```

## 团队推广路径

### 阶段 1：试点（1 个月）
```markdown

## 目标
验证 AI Coding 在团队的可行性

## 做法
- 2-3 名志愿者
- 选定 1-2 个非关键项目

- 总结经验

## 产出
- 试点报告
```

```markdown

## 目标
扩展到 30-50% 团队成员

## 做法
- 培训所有感兴趣的人
- 建立内部 Wiki
- 完善 agents.md
- 建立 Review 流程

## 产出
- 完整规范文档
- 培训材料
- 反馈机制
```

```markdown

## 目标

## 做法

- 持续优化

- 团队效率提升
```

## 常见上手问题

### 问题 1：不知道用什么 Prompt
**解决**：
- 提供 Prompt 模板库
- Buddy 演示
- 录制 Prompt 教程

### 问题 2：AI 输出不符合规范
**解决**：
- 完善 agents.md
- 给 AI 反例
- 多轮迭代

### 问题 3：Review 反馈看不懂
**解决**：
- 培训新人 Review 礼仪
- 团队 Review 示范
- 1-on-1 讲解

### 问题 4：担心被 AI 取代
**解决**：
- 强调"会用 AI 的人取代不会用的人"
- 展示 AI Coding 提效案例
- 鼓励探索、创新
