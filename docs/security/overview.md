# 安全、合规与成本：总览
AI Coding 引入了新的风险类别：**代码泄露、依赖注入、合规问题、成本失控**。

本章帮你系统性地管理这些风险。

## 四大风险类别
| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **[敏感信息泄露](/security/secrets)**| 客户数据、密钥泄露 | 去敏、本地化 |
| **[依赖与合规](/security/dependencies)**| 引入恶意/废弃包 | 依赖审计 |
| **[Prompt Injection](/security/prompt-injection)**| AI 被诱导执行恶意操作 | 输入过滤、隔离 |
| **[成本失控](/security/cost)**| Token 费用爆炸 | 监控、配额 |

## 风险地图
```
                敏感信息
                   ↑
                   │
    Prompt         │         依赖
  Injection  ←──── AI ────→  安全
                   │
                   ↓
                成本控制
```

## 风险评估矩阵
| 风险 | 概率 | 影响 | 等级 |
| --- | --- | --- | --- |
| API Key 泄露给云端 AI | 高 | 高 |  高 |
| 客户数据被上传 | 中 | 高 |  高 |
| AI 推荐恶意包 | 中 | 中 |  中 |
| Prompt Injection | 低 | 中 |  中 |
| Token 费用爆炸 | 中 | 中 |  中 |
| AI 训练数据包含敏感信息 | 低 | 高 |  中 |

## 安全原则

### 1. 零信任
> 默认 AI 是不安全的，所有输出都需要审查。

### 2. 最小暴露
> 只给 AI 必要的最小上下文。

### 3. 防御纵深
> 多个层级防护，一个失效不影响整体。

### 4. 可审计
> 所有 AI 操作都有记录、可追溯。

## 团队安全规范示例
```markdown

## 团队 AI Coding 安全规范

### 禁止事项
- 不要把含 API Key 的代码发给 AI
- 不要把客户数据发给 AI
- 不要在公共 AI 工具处理公司机密
- 不要未经审查就合并 AI 引入的依赖

### 必须事项
- 代码去敏后再发给 AI
- 启用 AI 工具的 Privacy Mode
- 依赖变更必须审查
- 关键操作（支付、权限）必须人工确认

### 推荐做法
- 敏感项目用本地模型
- 定期审计 AI 生成代码
- 跟踪 Token 消耗
- 团队安全培训
```

## 合规检查清单
团队落地 AI Coding 前，必做这些合规准备：

- [ ] 法务/合规团队评审 AI 工具使用
- [ ] 明确哪些代码可/不可发给 AI
- [ ] 选择合适的部署模式（云端/本地）
- [ ] 启用 Privacy Mode
- [ ] 建立数据脱敏流程
- [ ] 设置成本预算
- [ ] 制定违规处理流程
- [ ] 培训团队安全意识

## 总结
> 安全合规是 AI Coding 的**底线**，不是可选项。
