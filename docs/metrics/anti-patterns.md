# 常见反模式
AI Coding 落地中容易踩的坑，整理成"必避清单"。

## 1. 信任类反模式

### 反模式 1.1：盲信 AI
```markdown
 "AI 写的应该没问题，直接合并"
```

**问题**：AI 生成的代码有 30-50% 需要修改。

**正确**：

```markdown
 "AI 写的，先跑测试 + 自审 + 同事 Review，再合并"
```

### 反模式 1.2：跳过测试
```markdown
 "AI 都跑通了，不需要测试"
```

**问题**：AI 跑的"通过"不等于"正确"。

**正确**：

```markdown
 "AI 写的 + 补充测试（边界、错误场景）+ Review"
```

### 反模式 1.3：跳过 Review
```markdown
 "AI 写的很标准，不用 Review"
```

**问题**：标准 ≠ 正确 ≠ 符合业务。

**正确**：

```markdown
 "无论谁写的（包括 AI），都需要 Review"
```

## 2. 用法类反模式

### 反模式 2.1：一次给太多任务
```markdown
 "帮我做用户管理、订单管理、产品管理、财务系统"
```

**问题**：AI 容易混乱，生成大量问题代码。

**正确**：

```markdown
 "帮我做用户管理的列表 + 详情"
（一次一个）
```

### 反模式 2.2：没有上下文
```markdown
 "写个组件"
```

**问题**：AI 只能猜，结果完全不可用。

**正确**：

```markdown
 "按 agents.md 写一个用户列表组件"
```

### 反模式 2.3：用错模式
```markdown
 "创意探索时先写 20 页规范"（Spec Coding 错误用于 Vibe）
 "生产代码用 Vibe Coding 随便写"
```

**问题**：模式与场景不匹配。

**正确**：

```markdown
 按 [决策树](/modes/decision-tree) 选模式
```

### 反模式 2.4：不会停下来
```markdown
 "Vibe Coding 30 分钟本该停，做了 3 小时还在试"
```

**问题**：效率低下，沉迷探索。

**正确**：

```markdown
 严格时间盒，到点停止
```

## 3. 流程类反模式

### 反模式 3.1：跳过规划
```markdown
 "直接让 AI 写代码，不规划"
```

**问题**：复杂任务容易做歪。

**正确**：

```markdown
 "先 Plan，再实施"
```

### 反模式 3.2：不维护 agents.md
```markdown
 "agents.md 写完就锁进抽屉，从不更新"
```

**问题**：规范过时，AI 输出质量下降。

**正确**：

```markdown
 agents.md 与代码同步演进
```

### 反模式 3.3：没有团队规范
```markdown
 "每人用自己的 agents.md"
```

**问题**：团队代码风格混乱。

**正确**：

```markdown
 团队统一一份 agents.md
```

### 反模式 3.4：没有 PR 模板
```markdown
 "PR 标题乱写，描述空白"
```

**问题**：Review 困难，知识丢失。

**正确**：

```markdown
 用 PR 模板，AI 辅助填描述
```

## 4. 安全类反模式

### 反模式 4.1：明文密钥发给 AI
```markdown
 "把含 API Key 的代码发给 AI 优化"
```

**问题**：密钥泄露。

**正确**：

```markdown
 先去敏，再发给 AI
```

### 反模式 4.2：不启用 Privacy Mode
```markdown
 "默认设置，代码被用于训练"
```

**问题**：代码可能被第三方使用。

**正确**：

```markdown
 启用 Privacy Mode（Cursor Business / Claude Code）
```

### 反模式 4.3：信任 AI 推荐的包
```markdown
 "AI 推荐 react-super-utils-2，直接安装"
```

**问题**：可能是恶意包或不存在。

**正确**：

```markdown
 pnpm view 验证，检查维护情况
```

### 反模式 4.4：忽略 Prompt Injection
```markdown
 "用户输入直接拼接进 Prompt"
```

**问题**：AI 被诱导执行非预期操作。

**正确**：

```markdown
 使用结构化消息，输入验证
```

## 5. 工具类反模式

### 反模式 5.1：追新求全
```markdown
 "Cursor、Claude Code、Copilot、Tabnine 全用"
```

**问题**：每样都不深入，团队精力分散。

**正确**：

```markdown
 选 1-2 个工具深入用
```

### 反模式 5.2：只看工具不看流程
```markdown
 "换了 Cursor 效率没提升？再换一个"
```

**问题**：问题在流程不在工具。

**正确**：

```markdown
 工具 + 流程 + 规范一起改
```

### 反模式 5.3：不配置直接用
```markdown
 "装上 Cursor 就开始用，不配置"
```

**问题**：用了 80% 的能力。

**正确**：

```markdown
 配置 agents.md、模板、快捷键
```

## 6. 团队类反模式

### 反模式 6.1：单兵作战
```markdown
 "我用 AI Coding 很高效，但没分享"
```

**问题**：团队整体效率未提升。

**正确**：

```markdown
 分享 Prompt、模板、最佳实践
```

### 反模式 6.2：强制推广
```markdown
 "所有人必须用 Cursor，不管愿不愿意"
```

**问题**：抵触情绪，反而效率下降。

**正确**：

```markdown
 自愿 + 培训 + 渐进推广
```

### 反模式 6.3：无人负责
```markdown
 "大家都用，没人维护 agents.md、模板"
```

**问题**：规范逐渐失效。

**正确**：

```markdown
 指定 AI Coding Lead 负责维护
```

### 反模式 6.4：只看结果不看过程
```markdown
 "只看代码量，不看协作过程"
```

**问题**：短期高效，长期混乱。

**正确**：

```markdown
 度量代码质量 + 协作过程
```

## 7. 心理类反模式

### 反模式 7.1：AI 焦虑
```markdown
 "AI 这么强，我要被淘汰了"
```

**问题**：影响工作状态。

**正确**：

```markdown
 "会用 AI 的人取代不会用的人"
```

### 反模式 7.2：AI 依赖症
```markdown
 "任何代码都让 AI 写，自己不思考"
```

**问题**：能力退化。

**正确**：

```markdown
 AI 是外脑，关键决策必须自己来
```

### 反模式 7.3：完美主义
```markdown
 "AI 输出不够完美，要打磨到 100%"
```

**问题**：过度优化，浪费大量时间。

**正确**：

```markdown
 "80% 够好就够，剩下的留给迭代"
```

### 反模式 7.4：盲目乐观
```markdown
 "有了 AI Coding，所有问题都解决了"
```

**问题**：忽视 AI 的局限。

**正确**：

```markdown
 "AI Coding 是工具，不是银弹"
```

## 8. 流程类反模式（续）

### 反模式 8.1：忽视 Review 反馈
```markdown
 "Reviewer 说有问题？让 AI 改改就行了"
```

**问题**：Reviewer 的业务知识被浪费。

**正确**：

```markdown
 "认真理解反馈，必要时和 Reviewer 讨论"
```

### 反模式 8.2：Review 流于形式
```markdown
 "Review 只看代码风格，不看业务正确性"
```

**问题**：业务 Bug 漏过。

**正确**：

```markdown
 Review 重点：业务正确性、边界、安全
```

### 反模式 8.3：不做回顾
```markdown
 "AI Coding 用着，不总结不回顾"
```

**问题**：错过改进机会。

**正确**：

```markdown
 每月回顾，看哪些做得好/不好
```

## 9. 文档类反模式

### 反模式 9.1：文档不写
```markdown
 "AI Coding 不用写文档"
```

**问题**：6 个月后没人看得懂。

**正确**：

```markdown
 agents.md + 模块 README + 关键注释
```

### 反模式 9.2：文档过度
```markdown
 "100 页规范，没人看"
```

**问题**：规范流于形式。

**正确**：

```markdown
 短而精的规范
```

### 反模式 9.3：文档与代码脱节
```markdown
 "代码改了，文档没更新"
```

**问题**：文档误导。

**正确**：

```markdown
 文档与代码同步更新
```

## 10. 度量类反模式

### 反模式 10.1：不度量
```markdown
 "用着就行，不用度量"
```

**问题**：不知道效果，无法改进。

**正确**：

```markdown
 度量关键指标
```

### 反模式 10.2：度量指标错位
```markdown
 "只看 AI 调用次数"
```

**问题**：调用多不等于效果好。

**正确**：

```markdown
 度量目标指标（效率、质量、成本）
```

### 反模式 10.3：短期数据下结论
```markdown
 "用了 1 周感觉没用"
```

**问题**：学习曲线未考虑。

**正确**：

```markdown
 至少 1 个月数据再下结论
```

## 总结
> 避免反模式，比学习最佳实践更重要。

- 信任但验证
- 流程重于工具
- 团队重于个人
- 不要"为快而快"
